# 理解指南模版

> 本文是同目录下 `understanding-guide-template.md` 的中文翻译，仅供阅读。

一个读者，一件事：一位有能力但对这个模块陌生的人，他想**理解**这个缺陷，而不只是批准一个补丁。读完之后，他应该能不查任何资料就把这个 bug 讲给同事听。

存为 `<输出目录>/<slug>-understanding.md`。slug 与 issue 报告一致，两份文档互相链接。

长度随主题。一个自包含辅助函数里的一行 off-by-one，一页就够。调度器、page cache 回写路径、或锁序规则里的缺陷需要好几页，因为读者脱离周边设计就无法判断它。

## 结构

```markdown
# 理解：<用平实的话说这个缺陷是什么>

配套文档：<issue 报告路径>。先读那一份拿结论和修复方案。

## 一句话版本

五句话，不用行话：这个模块做什么、这里它本该做什么、它实际做了什么、
以及为什么这重要。只读这一节的人，即使漏掉细节，也应该抓对 bug 的形状。

## 术语表

读者需要的每个术语，各用一两句解释，按它们在后文首次出现的顺序排列。
包括那些"基础到不值得解释"的 —— 过度解释的代价是被跳过一行，
解释不足的代价是一个读不下去的读者。

- **<术语>** —— <平实的定义>。<它为什么会出现在这个 bug 里。>

## 这个模块是干什么的

模块在系统中的位置、它解决什么问题、谁调它、它调谁。先一段文字，再给出地图：

​```text
用户进程
  → syscall 层            <dir/>
    → 本模块              <dir/>
      → 后端设备          <dir/>
​```

明确点名公开面：哪些函数、syscall 或 ioctl 是外部世界进来的入口。
缺陷的可达性论证就架在这份清单上。

## 设计，以及为什么是这个设计

让 bug 变得讲得通的那一部分。

- **它维护的状态** —— 这里相关的结构体和字段，各自是什么含义。
- **不变量** —— 代码假定始终成立的性质。把陈述这些性质的断言、注释或锁规则引出来。
- **设计意图** —— 为什么选了这个结构：性能、硬件约束、兼容性、某个标准的要求。
  引出你找到这段理由的 commit、文档或规范。如果你是在推测意图而不是读到它，
  标明"推测"。
- **取舍** —— 这个设计放弃了什么。bug 通常就住在这个设计决定不处理的那部分里。

## 它本该怎么工作

用普通句子把一次正确的执行从头走到尾，每一步带 `file:line`。
读者需要先把能正常工作的路径装进脑子，坏掉的那条才有意义。

## 它在哪里出错

现在用触发输入把同一条路再走一遍。指出两次走查恰好分岔的那个点、
哪条不变量最先破掉、以及损害如何从那里传播到可见的失效。
行号与 issue 报告保持一致。

## 测试是怎么打中它的

触发用的测试准备了什么、调了哪个入口、断言了什么、以及为什么那个断言是正确的预期。
如果这个测试在任何方面是人为的，说清是哪方面、以及这是否削弱了论证。

## 历史

这一行是什么时候写的、当时那个 commit 在解决什么（`git log -L`、`git blame`）。
缺陷往往是原改动不需要处理的一个边界情形，把这一点说出来，比暗示当年写得草率要有用。
提一下同一区域过去相关的修复。

## 值得顺带了解的相邻概念

读者接下来会撞上、否则就得自己去查的邻近事物：这条路径周边的加锁方案、
这些对象的生命周期规则、标准里相关的那一节。要短，并且只写真正碰到这个 bug 的部分。

## 自测

三到四个读者读完之后应该能回答的问题。把答案也简短给出 —— 它们顺便充当了小结。

## 延伸阅读

具体的指路，不是书单：`Documentation/<file>`、规范的章节号、commit SHA、
下一个该读的源文件。说清每一条各适合用来解决什么。
```

## 比结构更重要的规则

- **要解释，不要复述代码。** 把几行代码换个说法讲一遍毫无增量。要说这些行为什么是这样、它们在保护什么。
- **术语不得先用后解释。** 扫一遍自己的草稿，检查每个行话的首次出现位置。
- **推测出来的设计意图要标成推测。** 从代码里读出目的是猜；commit message 或文档才是证据。把两者明显分开。
- **具体优于抽象。** 真实的数值、真实的大小、真实的结构体名。"4096 字节的页配 512 字节的扇区"能教人；"相关的粒度不匹配"不能。
- **报告和指南重叠的地方，数字必须完全一致。** 同样的行号、同样的 commit、同样的数值。读者在两份之间来回翻时，绝不该需要自己去调和两个版本。
- **这里长一点没关系。** 报告靠短来立身；指南靠不留缺口来立身。
