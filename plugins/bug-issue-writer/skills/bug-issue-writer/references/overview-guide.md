# 缺陷概览写作指南

概览用于快速了解这批缺陷及其影响，按 [overview 模板](../assets/overview-template.md) 汇总。默认保存为报告总目录下的 `BUG-OVERVIEW.md`；使用 subagent 写报告时，由主代理在合并并审核最终稿后统一维护概览。

## 确定汇总范围

- 新建概览或更新条目时，行为、影响和根因只取自本次审核通过的最终 issue。不要从旧稿、原始记录或样例补入最终报告未采用的附加案例、未经验证的能力或影响。
- 先读取已有概览，保留本次未涉及的条目和已有 ID。按根因计数，同一根因的不同入口或复现不重复算作独立缺陷；不要因重新排序而重编号，没有 ID 时不套用样例编号。
- 严重度只沿用已有确认的分级，可来自最终报告或对应复查、概览。缺失时省略该项分级，不自行评级；汇总分布不得把未分级项算作某个等级。
- 开头说明独立缺陷总数、已有严重度概况及主要影响。版本、提交、覆盖范围、原记录数和分级来源仅在有依据时写入，不复制样例中的项目名称、数量或结论。

## 写出条目

每项采用加粗的标题链接，带已有 ID 和严重度；下一行列出实际出错函数，必要时区分调用入口。随后只写“预期行为、实际行为、影响、根因”四条，每条一两句，不展开源码、完整测试或日志。

保留最终报告中影响结论的限定，例如有限观察窗口、权限前提未验证、非常规边界用法；将它们放入“实际行为”或“影响”。实测结果与源码推导应能区分，不能把“窗口内未发生”扩大为“永远不会发生”，也不能把未验证前提写成已成立。

若本次交付包含待补证据的草稿，在对应条目中保留该状态，开头统计区分确认项与待确认项，不把所有条目笼统写成已验证缺陷。

标题使用相对于概览所在目录的报告链接，指向当前审核通过的最终版，例如本次交付的 v2；不要照搬样例的旧版路径。这里的报告链接是概览必需内容，不适用单篇 issue 的“无额外链接”规则。

交付前核对条目数、根因合并、严重度统计和稳定 ID，并确认每个链接实际指向对应最终稿；局部更新后，总数应包含保留的未涉及条目。
